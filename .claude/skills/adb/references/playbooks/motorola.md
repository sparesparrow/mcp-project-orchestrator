# Motorola playbook (e.g. moto g54 5G, codename `cancunf`, MT6855 / Dimensity 7020)

Verified on a connected unit via triage: Android 15 (`V1TDS35H.83-20-5-8-6`), build type `user`, `flash.locked=1`, verifiedbootstate green, dynamic partitions, A/B (`slot_suffix` `_b`), `su` absent.

## Eligibility
- Retail/unbranded variants: unlockable via Motorola's official portal. Carrier-branded (T-Mobile/Verizon/etc.) are often refused ("device not eligible"): report and stop.
- Carrier/SIM-lock check before Gate 2 (hints, not proof): `getprop ro.carrier` (retail channels look like `retail`, `reteu`, `retin`, ...; carrier names like `tmo`, `vzw` mean branded), `getprop ro.boot.carrier`, the channel in the firmware/fingerprint, and whether the user bought it unlocked/retail. Final word: the portal's eligibility answer. Branded or unclear → tell the user before going on.
- Prereq on phone: Developer options > OEM unlocking ON and not greyed out. Over adb this is ambiguous: `getprop sys.oem_unlock_allowed` can be `1` while `settings get global oem_unlock_allowed` is `null` (seen on cancunf). Record both as hints; the real check is in fastboot (`fastboot getvar unlocked`, `fastboot oem get_unlock_data` succeeding). Phone must have internet access when toggling.
- Unlock portal: Motorola's "Unlock your bootloader" page on motorola-global-portal.custhelp.com. Candidate URL from a search summary (not fetched, possibly truncated): `https://motorola-global-portal.custhelp.com/app/standalone/bootloader/unlock-your-device-a`. **Verify the current URL** (WebSearch/WebFetch, official Motorola domain) before giving it to the user. A headless test run named a second candidate on the support domain, `https://en-us.support.motorola.com/app/standalone/bootloader/unlock-your-device-a`, as "official"; Motorola's support pages returned HTTP 401 to WebFetch here, so neither URL is verified. Never present either as confirmed: give the user the search phrase "Motorola unlock your bootloader" plus the candidates, labelled unverified, and let them confirm they are on a motorola.com page.

## Unlock (wipes data)
1. `adb -s <serial> reboot bootloader` (own confirmation; plan approval does not cover it). Check `fastboot devices`, then `scripts/fastboot_facts.sh <serial>`.
2. `fastboot oem get_unlock_data` prints several `(bootloader)` lines. Join them with no prefixes/spaces into one string and submit it at Motorola's unlock page with the user's Motorola ID. Motorola shows/emails a 20-character key. The browser work (account creation or "Forgot password", sign-in, submit, reading the verification email) follows `references/browser-steps.md`: Claude may drive a browser tool, the user types passwords, solves CAPTCHA/2FA and accepts the legal notice, and confirms the exact string before submit. Claude never invents a key.
3. After explicit yes for that command: `fastboot oem unlock <KEY>`. Some units need it confirmed on-screen with the volume/power keys. Phone factory-resets; user redoes setup, re-enables USB debugging. On the g54 the first call returned `OKAY` after ~30 s with no change; the second printed "Bootloader is unlocked! Rebooting phone to fastboot mode" and `getvar securestate` became `flashing_unlocked` (`getvar unlocked` is "not found" in the bootloader, `yes` in fastbootd). Compare the key with the email character by character (O vs 0, case-sensitive).
4. Bootloader warning screen on boot ("bootloader unlocked") is normal.

## Root (Magisk)
- Firmware: stock ROM for the exact retail channel/build matching `ro.build.fingerprint` (never older than installed patch; Motorola has anti-rollback). Use a source the user accepts and verify filename/hash.
- Image to patch: check `fastboot getvar all` / firmware for `init_boot`; Android 13+ launch devices usually use `init_boot`, devices upgraded may use `boot`. Patch `init_boot.img` if present, else `boot.img`.
- Patch on the phone with the Magisk app (`scripts/fetch_magisk.sh`), pull result, then read `fastboot getvar current-slot` right before flashing and run `scripts/flash_guarded.sh <init_boot|boot>_<that slot> <img> --serial <serial> --product <codename>`. After the unlock wipe, an OTA during setup can switch slot/build: disable Developer options > "Automatic system updates", re-triage, and re-match firmware if the build changed.
- **No exact firmware available (g54 case):** if `ro.bootimage.build.fingerprint` is a generic `Android/gsi_arm64/...` GKI fingerprint, the boot image is Google's GKI build and any Motorola firmware with the same GKI (compare fingerprint, `ro.bootimage.build.date.utc`, kernel banner) has an identical `boot.img`. Pull just `boot.img` with `scripts/remote_zip_extract.py`, patch with `scripts/magisk_host_patch.sh --preinit metadata`, flash from fastbootd. Full walkthrough and dead ends: `references/field-notes-moto-g54-cancunf.md`.
- vbmeta: only if the phone fails to boot after flashing; use the stock vbmeta from the same firmware with `--disable-verity --disable-verification` (may wipe data).
- Do not touch MediaTek calibration/boot-chain partitions: `preloader`, `lk`, `nvdata`, `nvram`, `protect1/2`, `persist`, `proinfo` (IMEI/baseband loss).

## Rollback
Verify the saved stock image's sha256, flash it via `flash_guarded.sh` (with `--serial`/`--product`) to the same slot that was flashed, `fastboot reboot`. Full recovery: Motorola Rescue and Smart Assistant (RSA) or flashing the complete stock firmware.
